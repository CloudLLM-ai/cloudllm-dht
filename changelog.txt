UNRELEASED

  - feat(rpc,traversal): the rpc manager, observers and every traversal:
    transaction ids matched on endpoint, short (1 s) and full (15 s)
    timeouts, the sorted result list with branch factor and short-timeout
    slots, find_data write tokens, get_peers (plain and two-phase
    obfuscated) with announce_peer, bootstrap, BEP 44 get and put,
    BEP 51 sample_infohashes and direct requests. Results leave as Events.
    Observers live in a reference-counted arena and a traversal is dropped
    with its last observer, like libtorrent's shared_ptr. All assigned
    test_dht.cpp cases pass; a traversal_replies fuzz target covers every
    response parser.

  - feat(storage): the DHT storage trait and its in-memory implementation
    (dht_storage_interface, dht_default_storage): BEP 5 peers with seeds,
    downloaders and BEP 33 scrape bloom filters, a 16-peer limit per IPv6
    /56, torrent/peer/item caps, BEP 44 immutable and mutable items with
    popularity-weighted eviction, expiry, BEP 51 info-hash samples. All 15
    test_dht_storage.cpp cases and the two storage simulation cases pass.

  - feat(ed25519): Ed25519 with libtorrent's 64-byte expanded secret keys
    (create_keypair, sign, verify, add_scalar, key_exchange) on
    curve25519-dalek, matching libtorrent's verification exactly (it
    accepts the malleated S+l that ed25519-dalek rejects) and signing with
    unclamped add_scalar keys. The twelve gnupg vectors and the BEP 44
    vectors pass; every signature is cross-checked against ed25519-dalek.

  - feat(item): BEP 44 items: signing payload, sign/verify_mutable_item,
    item_target_id, Item. Unlike libtorrent, an over-long payload is
    rejected on verify instead of verifying a silently truncated prefix.

  - feat(dos_blocker, dht_state, bloom_filter, announce_flags): the
    per-address rate limiter and ban table, saved DHT state (old and new
    node-id formats, tolerant loader), the BEP 33 bloom filter with the
    BEP 33 test vectors, and the announce flags.

  - fix(routing_table): two libtorrent bugs fixed in the port. (1) After
    splitting the last bucket, add_node erased the new bucket when it held
    no live node, even if it held replacements; those nodes were lost and
    their addresses stayed in the IP set forever, so with
    restrict_routing_ips such an IP could never be added again (found by
    the routing_table_ops fuzzer). (2) depth() cached -1 when first called
    on an empty table and returned it forever, so node::tick re-bootstrapped
    every ten minutes for good; depth() now recovers once nodes arrive.

  - feat(routing_table): the Kademlia routing table and node entries ported
    from libtorrent (routing_table.cpp, node_entry.cpp): buckets with
    replacement caches, splitting, the extended first buckets, prefix-slot
    spreading (classify_prefix, replace_node_impl), BEP 42 verified-node
    preference, one-node-per-IP and /24 (/64) restrictions, router nodes,
    IP filter hook, refresh scheduling, find_node, set_id, status and
    print_state. All 14 routing-table TEST_CASEs of test_dht.cpp are
    ported (60 tests), plus a routing_table_ops fuzz target that checks the
    structural invariants after every operation of an arbitrary sequence.

  - feat(foundation): the shared modules every work package builds on:
    Sha1Hash/NodeId with the XOR metric and distance_exp; BEP 42 ID
    generation and verification (crc32c; the five BEP 42 reference vectors
    pass); per-owner secret IDs; compact IPv4/IPv6 endpoint and node
    encodings; DhtSettings with libtorrent's defaults and its persisted
    subset; the message model (Query, MessageType, Want, ErrorCode) and the
    declarative verify_message with libtorrent's exact error strings; the
    injectable Time/Clock/Rng/Transport seam of the sans-IO core; and a
    test harness porting test_dht.cpp's mock_socket, msg_args and helpers.
    A message_parse fuzz target covers decode, verify tables and compact
    parsing.

  - docs: ARCHITECTURE.md (sans-IO design, storage trait, ed25519 key
    mapping, API sketch) and PORTING.md (every libtorrent file and TEST_CASE
    mapped to a module and one of four work packages, with the interfaces
    between packages). Placeholder modules for every package are declared
    in lib.rs so packages never conflict there.

  - feat(bencode): bencode decoder and encoder ported from libtorrent
    (bdecode.cpp, entry.cpp). Same depth/token/buffer limits, same error
    codes and error positions, soft errors (unsorted or duplicate keys,
    leading zeros), partial trees after a failed parse, and zero-copy nodes
    whose data_section is the exact source bytes (BEP 44 signs those).
    All 79 TEST_CASEs of test_bdecode.cpp that have a Rust counterpart are
    ported; a cargo-fuzz target checks decode/encode invariants.

  - chore(repo): CI (fmt, clippy -D warnings, tests on ubuntu and macos,
